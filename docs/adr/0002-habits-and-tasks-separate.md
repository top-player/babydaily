# 习惯与任务是两个独立模块

习惯（打卡、连续天数、累计次数、断签）与任务（主线/支线/每日、属性奖励）使用相互独立的数据模型与界面模块：打卡不等于完成任务。习惯打卡默认奖励 +1 自律值，奖励独立配置，不与任务奖励混用同一实体。

**Considered Options**
- 统一模型：把习惯建模为"每天自动重复的任务"。被否决：两者用户心智不同——任务的失败代价是每日结算扣属性，习惯的失败代价是断签归零；把断签规则与过期惩罚强加在同一实体上会让规则互相纠缠。用户想把同一行为既当任务又当习惯时，可以各自建一条，互不干扰。

**Consequences**
- 任务完成历史与习惯打卡历史分开存储，统计与热力图各自独立。
- 奖励数值结构在两边相似（可共享同一数值类型），但存储与结算逻辑独立。
